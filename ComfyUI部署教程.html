外部批量贴标
帕琪工坊 × ComfyUI

适用：同款衣服不同颜色、相似构图的批量贴标。先摆好首图，再自动校准其他颜色的相似位置，检查衣料褶皱、遮挡和光影。每张处理结果需要复核。

本机 CPU 安装已有 ComfyUI使用流程远程服务故障排查专用接口
针对你的电脑：R7 250 级别 / 1GB 显存 / 16GB 内存

默认只用 CPU，不用这张老 AMD 卡，不需要安装 CUDA 或 ROCm。ComfyUI 与模型在独立目录运行，不修改工坊本身的 Python 组件。每次只处理一张，只在 Logo 附近的小区域进行模型分析；合成与导出保留原图分辨率。CPU 处理可能较慢，首张还需加载模型，不承诺固定秒数。处理时可以返回工坊，或随时停止等待。预留至少 8GB 磁盘和足够可用内存；批次开始前关闭占内存的程序，先用两张图验证效果。

工作方式

  1. 位置：首图由用户确定。其他颜色先按相同比例同步，再通过局部 SIFT 特征、RANSAC 检查小幅偏移与旋转。没有足够匹配点时保留手动位置并提示，不做跨姿势猜测。
  2. 褶皱与凸起：Depth Anything V2 Small 分析局部相对深度，对原始 Logo 做小幅连续位移；原衣物的明暗和纹理参与光影融合。相对深度不等于真实 3D，无法精确重建所有针织细褶。
  3. 遮挡：CLIPSeg 按胸前 / 内侧领标识别抽绳、拉链拉片、领口等前景，可靠区域擦除贴标对应像素。图案保持不透明，只有检测到遮挡的像素被删除；不通过整体透明度制造贴合。
  4. 边缘：透明或明显白底的衣物边界辅助限制贴标；白色衣服与白底难分时，关闭「保留白底 / 透明边缘」，在主图中用保护画笔处理。
  5. 成品：以原始 Logo 像素变形合成，不使用扩散模型重画文字，不需要大模型 checkpoint、LoRA 或 Gemini Key。

必须了解：轻量模型的语义掩码比较粗，细抽绳、低反差内领、复杂叠层可能漏检或误检。识别结果不是自动验收；界面会列出警告，异常的大面积擦除保留原标识。逐图看遮挡和位置，再勾选「已复核」导出。此流程适合作为辅助美工的初稿，不保证全自动成片。

一、本机 CPU 安装（推荐）

方法 A：随包安装脚本

  1. 完整解压工坊更新包到可写文件夹，保持 ComfyUI_PatchiSticker 文件夹与安装脚本在同级。先正常启动工坊，确认原有功能可用。
  2. 双击 安装外部贴标_CPU.bat。脚本会创建 外部贴标环境\venv，从官方 GitHub 下载 ComfyUI，安装 CPU PyTorch 和节点依赖，再从 Hugging Face 下载两个模型。首次需要网络；不下载浏览器。
  3. 已有 Python 3.14 可先直接使用。脚本不强制下载或更换 Python；若出现“没有匹配的 torch wheel”，说明外部组件暂不支持所选 Python，需要给此外部虚拟环境选择受支持版本，工坊本体不必更换。
  4. 看到安装完成后，双击 外部贴标环境\启动外部贴标_CPU.bat，保持控制台打开，等待显示服务地址 http://127.0.0.1:8188。
  5. 在工坊主页打开「外部批量贴标」，填上述地址，点击「保存并检查连接」。看到节点及 depth / segment 两模型就绪，即可使用。

不要用管理员身份启动；可写普通目录即可。网络失败可再次运行安装脚本，已完成的环境与缓存通常会复用。脚本不会自动更新已经存在的 ComfyUI；新版本兼容问题先记录控制台错误。

方法 B：手动安装

下面以 Windows PowerShell、D:\PatchiComfy 为例。先从 ComfyUI 官方仓库下载 master ZIP，解压并将内层目录重命名为 D:\PatchiComfy\ComfyUI。不是把外层 ZIP 文件夹再套一层。

mkdir D:\PatchiComfy
cd D:\PatchiComfy
py -3 -m venv venv
.\venv\Scripts\python.exe -m pip install --upgrade pip
.\venv\Scripts\python.exe -m pip install "torch>=2.6" torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu
.\venv\Scripts\python.exe -m pip install -r .\ComfyUI\requirements.txt

将更新包里的整个 ComfyUI_PatchiSticker 文件夹复制到 D:\PatchiComfy\ComfyUI\custom_nodes\。确认目录直接包含 __init__.py、engine.py、semantic.py。

cd D:\PatchiComfy
.\venv\Scripts\python.exe -m pip install -r .\ComfyUI\custom_nodes\ComfyUI_PatchiSticker\requirements.txt
.\venv\Scripts\python.exe .\ComfyUI\custom_nodes\ComfyUI_PatchiSticker\prepare_models.py
cd .\ComfyUI
..\venv\Scripts\python.exe main.py --cpu --listen 127.0.0.1 --port 8188

首次模型准备下载到节点下 models\depth 与 models\segment，需要网络。真正执行任务时只读取本地模型，不临时下载。可用 PATCHI_MODEL_DIR 指定模型总目录；目录下仍须有 depth / segment 两个子目录。不要只下载一个权重文件，处理器、词表和 config 也需要。

二、已有 ComfyUI / 便携版

  1. 关闭 ComfyUI，复制节点文件夹到它的 custom_nodes。
  2. 用该 ComfyUI 自己的 Python 安装依赖并准备模型。NVIDIA Windows 便携版通常使用根目录的 python_embeded\python.exe（拼写依版本），不要用工坊的 Python 代替。
  3. CPU PyTorch 至少 2.6，以便安全加载旧格式权重；当前 ComfyUI 可能有更高要求，以其 requirements 为准。已有 NVIDIA GPU 环境不必为本节点重装 CPU Torch；本节点本身固定在 CPU 推理，避免显存不足。
  4. 按下面示例运行，再重启服务检查节点。无需安装参考项目或额外绘图节点。
# 在便携版根目录中执行；按实际 Python 目录修改
.\python_embeded\python.exe -m pip install -r .\ComfyUI\custom_nodes\ComfyUI_PatchiSticker\requirements.txt
.\python_embeded\python.exe .\ComfyUI\custom_nodes\ComfyUI_PatchiSticker\prepare_models.py
.\python_embeded\python.exe -s .\ComfyUI\main.py --windows-standalone-build --cpu --listen 127.0.0.1 --port 8188

三、批量贴标使用流程

  1. 在「制作主图」编辑器准备：上传同款颜色图与 Logo，首图摆好大小、位置和角度，点击批量贴标，必要时逐图微调。画布可用原分辨率或 2500×2500。
  2. 主页进入「外部批量贴标」：点击「读取制作主图当前贴标」。它读取快照，不会覆盖主图编辑器。支持每图 1–8 个 Logo；单图上限 3200 万像素，单次 1–80 张，总请求有大小上限，大批次建议分组。
  3. 也可以直接准备：在独立入口上传颜色图和一个 Logo，点击首图画布放置，左侧调整位置、宽度和角度，再点「把首图位置同步到所有颜色图」。点选其他颜色可微调。直接上传保留原图宽高。
  4. 设置部位：依次选择每个 Logo，胸前选择普通衣料，领标选择「内侧领标」。如果是从主图读取，默认全是胸前，内领标必须手动选择。设置首图部位后再次同步可将部位和位置一并传给其他颜色。
  5. 开始批量处理：工作区显示正在上传、排队、位置校准、模型识别和合成。处理期间可以切图观察，返回工坊做其他事；此入口保持后台运行。模型在外部 ComfyUI 主机执行。
  6. 立即停止：立刻停止本地等待、后续图片和结果回填；已完成结果保留。接口只删除本任务的队列项，并向专用节点发送取消标记，不调用会影响其他用户的全局 interrupt。正在执行的 CPU 推理会在当前推理阶段完成后检查取消，无法瞬间终止底层算子。
  7. 复核导出：看原图对比，检查领口与抽绳、浮空和衣料边缘。逐图勾选「已复核」，导出 ZIP，默认原格式原文件名（重名追加编号）和当前画布分辨率；JPEG 白底，PNG / WebP 可保留透明。

调整过位置、部位的图片会标记「需重新处理」，不能沿用旧结果导出。重新开始会创建新批次，先导出需要保留的旧结果。刷新恢复本次独立入口的图片与任务；重启工坊启动器才开始空白工作。重启 Python 助手会丢失其临时结果，应先导出。外部 ComfyUI 输入与输出文件会留在它的 input / output 下，可在任务结束后自行清理。

四、在另一台电脑或服务器部署

在另一台机器按上述步骤部署 ComfyUI 与本节点、准备模型。局域网机器可用 --listen 0.0.0.0 --port 8188 --cpu 启动，并在防火墙中允许工作电脑访问。工坊入口填那台机器的局域网地址，例如 http://192.168.1.20:8188。节点当前使用 CPU，远程机器的 CPU 越快通常越有帮助。

公网不要直接暴露无认证的 ComfyUI。通过现有 VPN 或带认证的 HTTPS 反向代理访问；入口支持可选 Bearer 令牌，令牌只在当前助手进程中保存，重启后重填，不写入工作内容。代理应同时转发 /prompt、/history、/upload/image、/view、/queue、/object_info 和 /patchi/sticker/*，并允许足够的上传大小。运行此流程不需要跨域浏览器设置，由本机助手转发。

五、常见问题

现象检查与处理
连接失败ComfyUI 控制台是否仍打开；浏览器访问 8188 能否打开；地址别填工坊的 8765；远程检查防火墙和代理认证。
HTTP 404 / 没有 PatchiSticker节点目录不能套两层；检查 ComfyUI 启动日志中的 IMPORT FAILED。用同一个 Python 安装 requirements，重启 ComfyUI。
depth / segment 未就绪在 ComfyUI 环境重新运行 prepare_models.py，只会补齐模型缓存。huggingface.co 必须可访问。人工下载时保留完整处理器与权重文件。
torch 找不到 wheel / DLL 导入失败使用受当前 PyTorch 支持的 64 位 Python；已有 3.14 可先试，外部环境失败再使用兼容版本。DLL 错误查看 PyTorch 官方 Windows CPU 安装说明及 VC++ 运行库。不要更换工坊工作环境。
首张长时间等待CPU 加载和推理较慢，查看实时记录与 ComfyUI 控制台，先做一张。不要反复点击开始。等待不影响返回工坊；需要时立即停止。
OOM / 内存不足关闭大程序，一次 2–5 张，一个批次串行；减少不必要 Logo。无需将全部源图放大到 2500。模型仍仅分析最长 448 像素的局部，深度输入为 392，CLIPSeg 默认 352。
校准不动 / 位置没改变图案、拉链、缝线特征不足或变化过大时会保留手工坐标。需同款相似构图，跨姿势不是本流程目标；先手工对齐差异较大的图。
领口 / 抽绳没擦除确认 Logo 部位选对；轻量语义分割不保证细物体，需人工修正。可在主图编辑器使用原图保护画笔获得可靠的遮挡，再单独导出该图。外部成品不会自动回写主图，避免两套版本混淆。
白色衣服被裁错 / 边缘不准关闭边缘选项，重新处理；复杂背景建议透明底，透明输入会使用原图 alpha 边界。
重启后找不到任务结果临时结果保存在工坊助手进程中，关闭前先导出。单纯刷新网页不会清空工作；重新运行启动器开始新工作。

六、专用接口与自定义

工坊本机接口只接受从工坊地址发出的操作请求。其他应用可直接调用外部 ComfyUI 节点：

  • GET /patchi/sticker/status：protocol=1、CPU 设备和模型准备情况。
  • POST /upload/image：ComfyUI 原生素材上传；接口自动去重上传参考图与 Logo。
  • POST /prompt：提交节点图。ComfyUI_PatchiSticker/workflow_api.json 为 API 版模板；需要替换输入文件名、首图路径和 Logo 坐标。它不是带节点坐标的可视化 UI 工作流，请不要直接当画布 JSON 拖入。
  • GET /history/{prompt_id}：读取最终图、透明贴标层和检查记录。GET /patchi/sticker/progress/{runId} 查看阶段。
  • POST /patchi/sticker/cancel，JSON {"runId":"本批次ID"}：只标记本批次取消。队列删除使用 ComfyUI 原生 /queue，按 prompt_id 删除。

节点名 PatchiSticker，输入 task_json 含 runId、original、reference、logos、options；所有图片路径均相对 ComfyUI input，不允许越界路径。logos 包含 image、id、x/y/w/h/rotation（当前原图像素）、role（chest / neck）、linked（是否按首图校准）。输出 0 为最终 RGBA 图、1 为透明贴标层、2 为 JSON 检查记录。主界面采用 API 工作流自动构建，无需手工搭建节点。
